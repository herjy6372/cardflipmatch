# 두근두근 카드 뒤집기

HTML·CSS·JavaScript로 만든 PC·모바일용 메모리 게임입니다. 쉬움·보통·어려움을 선택하고 캐릭터와 함께 50라운드에 도전합니다. Firebase 설정 전에는 로컬 순위를 사용하며, 설정 후에는 Firestore 공유 순위를 이용할 수 있습니다.

## 실행

로컬 게임은 `index.html`을 Chrome/Edge에서 열면 됩니다. 별명·나이·성별·캐릭터·난이도를 선택하고 게임을 시작하세요. 나이·성별은 ‘선택 안 함’이 있으며 저장하거나 전송하지 않습니다.

Firebase 모드에서는 HTTP/HTTPS로 실행해야 합니다. Python이 있다면 프로젝트 폴더에서:

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

`http://127.0.0.1:8765`로 접속합니다. 다른 기기는 PC의 127.0.0.1 주소에 접속할 수 없으므로 배포한 웹 주소가 필요합니다.

## 난이도와 게임 규칙

모든 난이도는 같은 카드 수를 사용하고 제한 시간이 다릅니다. 난이도는 게임 시작 전 선택하며, 새 게임에서도 유지합니다.

| 라운드 | 카드 수 | 쉬움 | 보통 | 어려움 |
| --- | --- | --- | --- | --- |
| 1–5 | 4 | 36→32초 | 30→26초 | 22→18초 |
| 6–10 | 8 | 48→44초 | 38→34초 | 28→24초 |
| 11–15 | 12 | 60→56초 | 46→42초 | 34→30초 |
| 16–20 | 16 | 72→68초 | 54→50초 | 40→36초 |
| 21–25 | 20 | 84→80초 | 62→58초 | 46→42초 |
| 26–30 | 24 | 96→92초 | 70→66초 | 52→48초 |
| 31–35 | 28 | 108→104초 | 78→74초 | 58→54초 |
| 36–40 | 32 | 120→116초 | 86→82초 | 64→60초 |
| 41–45 | 40 | 144→140초 | 102→98초 | 76→72초 |
| 46–50 | 48 | 168→164초 | 118→114초 | 88→84초 |

클릭·터치 또는 Tab과 Enter/Space로 카드 두 장을 엽니다. 같은 그림은 100점, 다른 그림은 0.5초 후 닫힙니다. 라운드 성공 시 남은 정수 초×10점을 더하며, 점수는 다음 라운드에 누적됩니다.

1–49라운드 완료 화면에서는 다음 라운드로 진행하거나 포기합니다. 시간 초과·포기·50라운드 완료 때만 최종 기록을 저장합니다. 마지막 미완료 라운드의 짝 점수도 포함합니다. 총 플레이 시간은 라운드 진행 시간만 합산하고 완료 안내에서 기다린 시간은 제외합니다. 새 게임은 1라운드·0점부터 시작합니다. 페이지 이탈/새로고침은 진행 중 게임을 복원하지 않습니다.

다른 탭에서도 게임 시간은 흐르고 배경음만 멈춥니다. 배경음·효과음은 각각 음소거와 볼륨을 조절할 수 있습니다.

## 순위와 저장

순위는 **같은 난이도·난이도 버전·점수 버전**끼리 비교합니다. 높은 총점 → 많은 완료 라운드 → 짧은 총 시간 → 적은 총 시도 순입니다. 모두 같으면 공동 순위(1,1,3)입니다. 같은 별명의 여러 게임도 각각 기록합니다.

로컬 `cardFlipMatch:v4`에는 전체 난이도 합계 최근 500개 종료 기록과 캐릭터·오디오·난이도 설정을 보관합니다. 과거 v2/v3 데이터는 원래 키에 남기며 설정만 이어 사용합니다. 변경 전 난이도의 기록을 새 순위에 섞지 않습니다. 저장이 차단되면 현재 실행의 메모리 기록으로 계속할 수 있지만 새로고침 후 보존되지 않습니다.

Firebase 활성화 시 v4 미전송 기록을 업로드하고 공유 순위 상위 100개를 실시간으로 보여 줍니다. 연결 실패 시 로컬 기록을 유지하고 연결 복구·재실행·‘다시 동기화’ 때 재시도합니다. 500개 보관 한도를 넘기면 오래된 미전송 기록도 제외됩니다. 별명과 게임 기록은 공유 순위에서 공개됩니다. 나이·성별은 저장·전송하지 않습니다.

## Firebase 설정

현재 기본값은 `enabled:false`이며 실제 Firebase 프로젝트는 아직 연결하지 않았습니다.

**[Firebase 설정 안내](docs/firebase-setup.md)** 순서대로 프로젝트·웹 앱 생성 → 익명 로그인 활성화 → Firestore 생성 → 규칙/색인 적용 → `js/firebase-config.js` 입력 및 활성화를 진행하세요.

설정 파일은 `firebase.json`, `firestore.rules`, `firestore.indexes.json`입니다. 규칙은 레코드 필드와 점수 범위를 검증하고 수정·삭제를 막습니다. 클라이언트 점수만으로 실제 플레이를 증명할 수는 없으며, 경쟁이나 보상이 있는 서비스에는 별도 서버 검증이 필요합니다.

## 파일 구성

- `js/config.js`: 카드·난이도·라운드·점수·캐릭터 설정
- `js/game.js`: 게임 상태·타이머·결과·순위 화면
- `js/storage.js`: v4 로컬 기록·난이도별 순위·미전송 기록
- `js/firebase-config.js`: 프로젝트 연결 설정
- `js/cloud.js`: 익명 인증·업로드·재시도·실시간 순위
- `js/character.js`, `js/audio.js`: 캐릭터·음원 동작
- `index.html`, `css/style.css`: 화면·반응형 스타일

## 테스트

Node.js와 Playwright가 있는 환경에서:

```powershell
node tests/game.test.cjs
node tests/media.test.cjs
node tests/cloud.test.cjs
```

설치된 Chrome을 사용한다면 `GAME_TEST_BROWSER` 환경변수로 실행 파일을 지정합니다. 게임 테스트는 파일 실행, 미디어 테스트는 HTTP 게임 테스트 및 음원/캐릭터 실패 대응을 확인합니다. 동기화 테스트는 Firebase SDK 대역으로 오프라인 보관·재시도·중복 방지·구독 종료를 확인하며 실제 서버·규칙 배포를 검증하지는 않습니다. 결과와 스크린샷은 `.tools/test-results/`에 저장합니다.

난이도 설정 변경 시 `.tools/build-firestore-rules.cjs`로 규칙의 누적 점수/시간 상한을 다시 생성하고 버전·문서·테스트도 함께 갱신해야 합니다.

기존 `docs/game-plan.md`, `docs/game-design.md`, `docs/test-checklist.md` 등은 이전 구현 당시의 문서입니다. 현재 동작과 설정은 이 README와 Firebase 설정 안내를 기준으로 확인하세요.
