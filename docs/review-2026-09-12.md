# 다른 PC 개발본 검토 결과

현재 README 및 갱신된 기획서의 누적 점수·ROUND_CLEAR·게임 전체 순위 규칙을 기준으로 검토했다. 게임 소스는 수정하지 않았다.

## 발견한 문제

### P2: 작은 태블릿 화면에서 6열 카드의 터치 너비가 부족함

- 재현: 10라운드(24장)에 진입한 뒤 화면을 600×900으로 설정한다.
- 실제 브라우저 측정: 카드 37.83×47.28 CSS px, 6열. 기획서의 최소 44×44px 목표보다 너비가 작다.
- 원인: css/style.css의 태블릿 구간에서도 활성 레이아웃이 210px 캐릭터 열을 유지하고, 보드는 최대 6열을 사용한다. 가용 너비가 줄어들어 카드가 좁아진다.
- 영향: 작은 태블릿 및 좁은 창에서 10라운드 이후 터치 오선택 위험이 커진다. 전체 페이지의 가로 넘침 여부만 검사하면 이 문제를 놓친다.
- 권장 수정: 좁은 태블릿에서는 캐릭터를 위쪽으로 이동하거나 보드 열 수를 줄여 카드 너비를 확보한다. 카드 수와 난이도는 유지한다. 600·640px에서 24·30·36·48장 각각의 실제 버튼 너비도 검증한다.

## 이번에 직접 확인한 동작

- 로컬 HTTP 서버와 앱 내 Chromium 브라우저에서 실행 성공.
- 빈 입력으로 시작이 진행되지 않음, 별명과 선택 안 함 옵션으로 시작 가능.
- 여자 캐릭터 선택 및 인사·대기·격려·성공·실패 표시.
- 1라운드에서 카드를 실제로 열어 그림을 확인하고 불일치 복구 후 두 쌍을 완성함.
- 2라운드 진입 시 16장, 30초, 이전 점수 360점 유지.
- 실제 30초 경과 후 시간 초과, 최종 360점·1라운드 완료·3회 시도 표시 및 순위표 기록 확인.
- 새 게임에서 1라운드·0점·0회로 초기화.
- 추가 UI 자동 클릭으로 1~9라운드 완료 후 10라운드 진입. 이 구간은 DOM의 카드 ID로 짝을 찾아 클릭했으므로 사람의 기억력·난이도 평가와는 다름.
- 10라운드에서 포기 후 최종 10,080점 = 짝 점수 7,600 + 보너스 2,480 확인.
- 처음으로 복귀, 남자 캐릭터 선택, 배경음 꺼짐 표시 확인.
- 320px 플레이·결과·순위 화면과 600px 플레이 화면 확인.
- 이번 관찰 중 브라우저 콘솔 error/warn 없음.

## 코드·자산 검사

- js/의 JavaScript 파일 문법 검사 통과.
- Node VM에서 config/storage 로딩 후 1~50라운드 카드 수·고유 ID·짝당 2장 검사 통과.
- 잘못된 라운드 0·51·소수·NaN 거부 확인.
- 캐릭터 PNG 8개 전체 로딩 성공. idle/static-idle은 2172×724, reactions/static-poses는 971×1620으로 설정값과 일치.
- 기존 tests/game.test.cjs, tests/media.test.cjs는 내용을 검토했지만 이번 실행에서 전체 재실행하지 않았다. 이전 테스트 통과 기록을 이번 결과로 간주하지 않았다.

## 검증 범위의 한계

이번 플레이에서 중단을 일으키는 오류는 발견하지 못했지만, 모든 상황의 무오류를 보장하지 않는다. 11~50라운드 전체 플레이, 실제 모바일 기기의 터치·사운드, 저장 차단/이미지 누락/자동재생 거부의 강제 재현 및 효과음 청감은 이번 확인에 포함하지 않았다. 음소거는 UI 표시 전환을 확인했으며 실제 스피커 출력 검증은 아니다.

검토용 로컬 주소에 별명 ‘검토테스트’의 종료 기록 2개가 생성되었다. 기존 순위 기록은 삭제하지 않았다.
