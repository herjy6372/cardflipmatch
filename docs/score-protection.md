# 무료 요금제의 점수 조작 방지

Firebase Spark 요금제를 유지합니다. 서버 규칙은 실제 카드 플레이를 증명하지 않으며, 정상 범위 안에서 꾸민 기록과 새 익명 계정을 만드는 공격은 막지 못합니다. 완전한 플레이 검증에는 서버에서 카드 상태와 입력을 처리하는 구조가 필요합니다.

## 적용한 검사

- 누적 짝 수, 완료 라운드, 종료 사유, 점수 공식과 난이도별 상한을 검사합니다.
- 완료한 라운드의 남은 시간 보너스와 실제 사용 시간의 관계를 검사합니다. 라운드별 정수 초 버림을 허용하되, 시간 초과한 마지막 라운드에는 전체 제한 시간이 사용되어야 합니다.
- 온라인 기록은 시도 1회당 최소 100ms를 요구하며, 틀린 짝의 500ms 대기 시간을 고려합니다. 이는 온라인 기록의 최소 조건이며 실제 사람의 플레이 증명은 아닙니다.
- 서버 생성 시각을 순위의 동점 정렬 시각으로 사용합니다. 로컬 종료 시각이나 클라이언트 시계를 서버 제출 시각으로 인정하지 않습니다.
- 기록과 계정별 제출 상태를 같은 원자적 트랜잭션에 저장합니다. 한 번에 여러 기록을 등록하거나 상태만 갱신할 수 없습니다.
- 같은 익명 인증 UID는 10초마다 한 건을 제출할 수 있습니다. 클라이언트는 대기 중 기록을 로컬에 보관하고 11초 후 재시도합니다. 다른 탭과 경합하는 경우에도 서버 규칙이 간격을 검사합니다.
- 기존 기록의 수정·삭제, 다른 계정의 제출 상태 접근과 목록 조회를 금지합니다. 정상적인 중복 업로드 재시도는 기존 문서를 확인하고 쓰기를 생략합니다.

## 실행 주소

- GitHub Pages: https://herjy6372.github.io/cardflipmatch/
- Firebase Hosting: https://cardflipmatch-herjy6372.web.app/

두 주소는 같은 Firestore 순위를 사용합니다. 브라우저의 로컬 기록·설정·익명 UID는 사이트 주소마다 별도로 보관됩니다. GitHub Pages는 main에 push하면 GitHub Actions가 게임 파일만 dist로 빌드해 배포합니다.

## 검증

`node tests/cloud.test.cjs`는 오프라인 큐, 중복 응답, 제출 대기와 타임스탬프 변환을 SDK 대역으로 검사합니다.

Java 21 이상과 공식 Firebase CLI가 있으면 다음 명령으로 실제 Firestore 규칙을 로컬 에뮬레이터에서 검사합니다.

```sh
firebase emulators:exec --only firestore --project demo-cardflipmatch "node tests/firestore-rules.test.cjs"
```

규칙 테스트는 150개 난이도/라운드 조합의 정상 포기·시간 초과 기록과 전체 완료를 검사하고, 점수·시간 조작, 잘못된 소유자, 서버 시각 우회, 연속 제출과 변경·삭제 공격을 검사합니다. 이 테스트는 localhost 에뮬레이터만 허용하므로 가상 점수가 운영 순위에 들어가지 않습니다.

서버 규칙을 강화하기 전 열린 오래된 페이지는 새로고침해야 새 제출 트랜잭션을 사용합니다. 오프라인 기록도 현재 서버 규칙에 통과하는 경우에만 업로드됩니다.

2026-10-01 검증 결과: Firestore 에뮬레이터에서 정상 종료 기록 303개와 조작·권한·연속 제출 검사를 통과했습니다. 전체 게임/미디어 회귀 테스트와 동기화 테스트도 통과했습니다. GitHub Actions 배포가 성공했고 두 사이트의 게임 파일 25개를 확인했습니다(텍스트의 Git 줄바꿈 변환 허용, 이미지/음원은 바이트 일치). 두 실제 사이트에서 같은 순위표의 실시간 갱신과 새 서버 시각 기록을 확인했으며, 이번 확인용 온라인 기록 두 개를 정리했습니다.
