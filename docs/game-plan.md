# 두근두근 카드 뒤집기 (Card Flip Match) 개발 기획서

뒤집힌 카드 두 장을 선택하여 같은 그림의 짝을 찾는 싱글 플레이 메모리 게임이다. 1~49라운드 성공은 게임 도중의 완료 안내이며 점수판을 공개하지 않는다. 시간 초과·50라운드 전체 완료·사용자 포기 때만 게임 전체의 누적 총점과 로컬 순위를 공개한다. 시작 전 별명·나이·성별을 선택한다. 구현 및 실제 검증 결과는 test-checklist.md를 함께 참고한다.

## 1. 개발 방식과 제한 조건

- HTML은 화면 구조, CSS는 레이아웃과 카드 뒤집기, JavaScript는 상태와 게임 규칙을 담당한다.
- 프레임워크와 빌드 도구 없이 로컬 `index.html`을 열어 기본 게임을 실행할 수 있게 한다. 스크립트는 `defer`로 불러오며 핵심 데이터에 `fetch`나 외부 모듈을 사용하지 않는다.
- 카드 그림은 이모지, 뒷면과 배경은 CSS로 제작한다. 카드 전환에는 `transform: rotateY`와 `backface-visibility`를 사용한다.
- 1~50라운드는 같은 규칙에 설정값만 달리 적용한다. 별도 맵이나 스토리 스테이지를 만들지 않는다.
- 제외 기능: 회원가입·로그인, 실시간 멀티플레이, 결제·쇼핑, 복잡한 서버·데이터베이스, 위치·카메라·마이크 권한, 외부 API에 의존하는 핵심 기능, 복잡한 캐릭터 성장, 대규모 3D 게임.
- 3분 배경음과 남자·여자 2D 사용자 캐릭터 선택 및 애니메이션, 시작 전 플레이어 정보 입력과 종료 후 로컬 순위는 확정 구현 범위다. 순위에 필요한 기록 저장은 필수이며, 개별 최고 기록 요약·테마는 선택 기능이다. 선택 효과음은 준비된 기존 파일로 이번 구현에 적용한다. 미디어 로딩·저장·재생에 실패해도 기본 게임은 실행되어야 한다.

### 확정 난이도

기존 구현 검토용 권장안을 최종 채택하여 원안을 대체한다. 아래 설정을 1~50라운드의 구현 기준으로 사용한다. 승리 조건은 현재 카드 수 ÷ 2쌍을 모두 찾는 것이다.

| 라운드 | 기본 배열 | 짝 수 | 구간 시작 제한 시간 | 구간 내 라운드당 감소 |
| --- | --- | ---: | ---: | ---: |
| 1 | 2×2 | 2 | 30초 | 0초 |
| 2~4 | 4×4 | 8 | 30초 | 1초 |
| 5~9 | 4×5 | 10 | 40초 | 1초 |
| 10~19 | 4×6 | 12 | 50초 | 1초 |
| 20~29 | 5×6 | 15 | 60초 | 1초 |
| 30~39 | 6×6 | 18 | 75초 | 1초 |
| 40~50 | 6×8 | 24 | 90초 | 1초 |

제한 시간은 `구간 시작 시간 − (현재 라운드 − 구간 시작 라운드) × 감소량`이다. 모바일에서는 카드 수를 유지하면서 열 수를 조정한다. 카드가 늘어나는 구간의 체감 난이도는 플레이 테스트로 검증한다. 기본 기능은 1라운드 2×2·30초로 먼저 구현하고, 같은 규칙을 전체 라운드에 적용한다. 기본 배열은 행×열이며, 최대 카드 수는 48장(24쌍)이다.

## 2. 프로젝트 파일 및 폴더 구조

다음은 구현 파일 구조다. 실행은 루트 index.html을 사용한다.

```text
CardFlipMatch/
├── index.html          # 시작 안내, 상태 정보, 카드 판, 결과 영역
├── README.md           # 실행 방법과 조작법
├── css/
│   └── style.css       # 반응형 레이아웃과 카드 애니메이션
├── js/
│   ├── config.js       # 이모지 목록, 라운드 설정, 점수 상수
│   ├── game.js         # 상태, 카드 생성, 입력, 판정, 타이머, 화면 갱신
│   ├── storage.js      # 로컬 순위 기록과 캐릭터·오디오 설정 저장·복원
│   ├── character.js    # 캐릭터 선택, 상태별 애니메이션
│   └── audio.js        # 배경음 재생, 선택 효과음, 개별 음소거·볼륨
├── images/
│   └── characters/     # male/female 하위 폴더: 상태별 스프라이트와 정적 대체 이미지
├── sounds/             # 선택: flip/match/mismatch/success/fail.mp3
│   └── bgm/
│       └── background.mp3 # 3분 배경음
└── docs/
    ├── game-plan.md      # 개발 규칙과 완료 조건
    ├── game-design.md    # 게임 개요, 규칙, 화면과 MVP 기획
    └── test-checklist.md # 수동 검증 결과
```

스크립트는 설정 → 캐릭터·오디오 및 선택 모듈 → 게임 순으로 불러온다. 선택 기능을 사용하지 않을 때는 해당 스크립트 참조도 제외한다. 전역 이름 충돌을 줄이기 위해 하나의 게임 네임스페이스를 사용한다. 효과음은 직접 제작하거나 사용 허가를 확인하고 필요한 출처를 기록한다.

## 3. 화면 영역별 구성 요소

| 영역 | 구성 요소 | 표시와 동작 |
| --- | --- | --- |
| 상단 제목 | 게임명, 짧은 설명 | 모든 상태에서 표시 |
| 시작 안내 | 규칙, 클릭·터치 안내, 시작 버튼 | READY에서 표시 |
| 플레이어 정보 | 별명, 나이, 성별 | READY에서 입력·선택, 선택 안 함 제공 |
| 상태 정보 | 현재 라운드/50, 남은 시간, 남은 쌍, 누적 점수, 현재 라운드 시도 횟수 | PLAYING에서 실시간 갱신 |
| 카드 판 | 앞면 이모지, 공통 뒷면, 일치 표시 | PLAYING에서 조작 가능, GAME_OVER에서는 조작 금지 |
| 캐릭터 선택 | 남자·여자 미리보기와 선택 표시 | READY에서 선택, 플레이어 성별과 독립 |
| 캐릭터 표시 | 선택 캐릭터의 대기·응원·결과 동작 | 카드 판 밖에 배치 |
| 보조 조작 | 게임 중 포기, 종료 후 처음으로, 배경음·효과음 설정 | 상태에 맞게 표시 |
| 라운드 완료 | N라운드 완료, 다음 라운드 시작, 포기 | ROUND_CLEAR에서 표시, 점수판·순위·기록 저장 없음 |
| 결과 | 시간 초과·전체 완료·포기, 총점·누적 보너스·총 시간·총 시도·총 찾은 쌍·완료 라운드 수 | GAME_OVER에서만 표시 |
| 결과 조작 | 최종 총점 순위 보기, 처음으로 | 게임 종료 후 표시 |
| 순위 화면 | 같은 난이도·점수 버전의 게임 전체 총점, 공동 순위, 이번 기록 강조 | 결과에서 순위로 이동; 1라운드 새 게임 버튼 제공 |
| 안내 메시지 | 설정 오류, 선택 기능 사용 불가 안내 | 필요한 경우 짧게 표시 |

카드는 실제 `button` 요소로 만든다. 닫힌 카드의 접근성 이름에는 정답을 노출하지 않고, 열린 카드와 찾은 카드는 상태를 알린다. 결과 표시 시 결과 제목이나 주요 버튼으로 초점을 옮긴다. 시간 경고는 색과 텍스트로 함께 전달한다.

## 4. READY, PLAYING, ROUND_CLEAR, GAME_OVER 게임 상태

| 상태 | 의미 | 허용 입력 |
| --- | --- | --- |
| READY | 시작 안내 또는 카드 생성 준비, 타이머 정지 | 시작, 설정 변경 |
| PLAYING | 카드 선택과 현재 라운드 타이머 진행 | 유효한 카드 선택, 포기, 음소거 |
| ROUND_CLEAR | 1~49라운드 성공, 전체 게임은 진행 중 | 다음 라운드, 포기, 음소거 |
| GAME_OVER | 시간 초과·50라운드 전체 완료·포기로 게임 종료 | 총점 순위 보기, 새 게임, 처음으로, 음소거 |

- 첫 진입은 READY다. 시작 버튼을 누르면 준비 중 중복 입력을 막고, 카드 생성과 렌더링이 끝난 시점에 PLAYING으로 바꾸며 타이머를 시작한다.
- 1~49라운드의 모든 짝을 찾으면 ROUND_CLEAR로 이동한다. ‘N라운드 완료!’와 다음 라운드 버튼을 표시하고 타이머를 멈춘다. 결과 점수판·순위·기록 저장은 하지 않는다.
- 시간 초과는 `timeout`, 50라운드 전체 완료는 `complete`, 사용자의 포기는 `quit`로 GAME_OVER를 확정한다. 포기는 PLAYING과 ROUND_CLEAR에서 가능하다. 제한 시간을 넘긴 PLAYING에서 포기를 누르면 시간 초과를 우선한다.
- 다음 라운드는 누적 기록을 유지하고 현재 라운드의 카드·시간·시도만 초기화한다. 종료 후 새 게임은 항상 1라운드·누적 0점으로 시작한다. 종료한 게임을 같은 라운드에서 이어 재도전하지 않는다.
- 처음으로는 결과·순위 화면에서 READY로 돌아간다. 플레이 중에는 처음으로 대신 포기를 제공해 총점을 확정한다. 새로고침·페이지 이탈 시에는 진행 중인 게임을 복원하거나 자동 저장하지 않는다.
- 두 카드 판정 중에는 PLAYING을 유지하고 `isResolving`으로 카드 입력만 잠근다. 별도 게임 상태를 추가하지 않는다.
- GAME_OVER 진입은 한 번만 허용한다. 결과 확정 시 타이머와 뒤집기 예약을 해제하고 최종 수치를 고정한다. 결과와 순위는 같은 GAME_OVER 상태의 서로 다른 화면이며, 순위 화면을 반복 방문해도 기록을 중복 저장하지 않는다.

## 5. 저장해야 할 데이터

### 실행 중 메모리에 보관할 데이터 — 필수

| 데이터 | 내용과 용도 |
| --- | --- |
| `state`, `finalResult.reason` | 네 가지 게임 상태와 종료 사유 |
| `round`, `roundConfig` | 현재 라운드, 카드 수, 기본 열 수, 제한 시간 |
| `cards` | 카드별 고유 `id`, 짝 판정용 `pairId`, `emoji`, `isFlipped`, `isMatched` |
| `selectedCardIds` | 선택한 카드 ID 0~2개 |
| `isResolving`, `isPreparing` | 판정 중 카드 입력과 준비 중 중복 시작 방지 |
| `totalPairs`, `matchedPairs`, `attempts`, `score` | 전체 짝, 찾은 짝, 두 장 선택 횟수, 점수 |
| `startedAt`, `deadlineAt`, `remainingMs` | 시작 시각, 종료 시각, 실제 남은 시간 |
| `timerId`, `flipBackTimeoutId` | 타이머와 0.5초 복구 예약 정리용 핸들 |
| `gameId` | 판을 구분하여 이전 판의 지연 콜백을 무시 |
| `selectedCharacter`, `characterMotion`, `characterTimeoutId` | male/female 선택값, 현재 동작, 동작 복귀 예약 |
| `bgmAudio`, `bgmMuted`, `bgmVolume`, `sfxMuted`, `sfxVolume` | 단일 배경음 인스턴스와 배경음·효과음 개별 설정 |
| `totals`, `roundSettled` | 확정한 라운드들의 누적 점수·보너스·시도·찾은 쌍·플레이 시간·완료 라운드 수와 중복 합산 방지 |
| `finalResult` | 게임 종료 순간의 누적 총점·총 시간·총 시도·총 찾은 쌍·완료 수·도달 라운드 |
| `profile` | 현재 플레이어의 별명·나이·성별. 나이·성별은 메모리에만 보관 |

남은 쌍은 `totalPairs − matchedPairs`로 계산한다. 제한 시간 표시는 남은 밀리초를 초 단위로 올림하고, 성공 보너스는 내림한 정수 초를 사용한다. 시간 기준은 `Date.now()`로 통일하고 남은 시간은 0~제한 시간 범위로 제한한다.

### 플레이어 정보와 브라우저 저장 — 확정 추가

- 시작 전 별명 1~12자(앞뒤 공백 제거, 공백만 입력 금지), 나이 1~120세 또는 선택 안 함, 성별 남성·여성·기타·선택 안 함을 입력한다. 나이와 성별의 빈 안내 항목은 선택 완료로 취급하지 않는다.
- 나이·성별은 현재 실행 메모리에만 보관하며 저장·전송·순위 표시·난이도 계산에 사용하지 않는다. 캐릭터 선택과 성별은 독립적이다. 서버 전송·계정 기능은 없다.
- 저장 키: `cardFlipMatch:v3`, 스키마 3, 난이도 버전 `difficulty-v1`, 점수 버전 `run-total-v1`. 이전 v2 라운드별 기록은 그대로 보존하고 새 순위에 섞지 않는다. v3 데이터가 없을 때 v2의 캐릭터·오디오 설정만 읽어 이어 사용한다.
- 게임 종료 시 기록 ID·별명·난이도/점수 버전·도달 라운드·완료 라운드 수·종료 사유·누적 총점/보너스/플레이 시간(ms)/시도/찾은 쌍·기록 시각을 한 번 저장한다. 시간 초과·전체 완료·포기만 저장하며 중간 라운드 성공은 저장하지 않는다.
- 최근 500개 종료 게임을 유지한다. 같은 난이도·점수 버전의 전체 게임을 라운드 구분 없이 비교한다. 총점 내림차순 → 완료 라운드 수 내림차순 → 총 플레이 시간 오름차순 → 총 시도 오름차순이다. 모든 비교값이 같으면 공동 순위(1, 1, 3)이며 시각·ID는 같은 순위의 표시 순서만 결정한다.
- 동일 별명도 각각의 도전 기록으로 취급한다. 순위는 계정별 최고 기록이나 온라인 전체 순위가 아닌 이 브라우저의 도전 기록 순위다. 현재 기록은 강조한다.
- 캐릭터와 배경음·효과음 각각의 음소거·볼륨도 저장한다. 입력 폼의 별명·나이·성별 및 진행 중인 판, 재생 위치, 애니메이션 진행률은 복원하지 않는다.
- JSON 파싱, 스키마·필드·범위·중복 ID 검증과 읽기·쓰기 예외 처리를 한다. 저장 차단·용량 초과·손상 시 안내하고 기본값·메모리 기록으로 계속 진행한다. 별명은 HTML로 해석하지 않고 텍스트로 출력한다.
- 로컬 파일 실행과 정적 서버 실행은 저장 공간이 다를 수 있다. 서버는 기본 실행의 필수 요소가 아니다.

## 6. 사용자 입력과 처리 결과

| 입력 | 처리 조건 | 결과 |
| --- | --- | --- |
| 시작 클릭·터치 | READY이고 준비 중이 아님 | 1라운드 생성, 점수 초기화, PLAYING 시작 |
| 첫 카드 선택 | PLAYING, 남은 시간 있음, 잠금 없음, 닫힌 미일치 카드 | 카드 오픈, 첫 ID 저장 |
| 두 번째 카드 선택 | 위 조건과 같고 첫 카드와 다른 ID | 카드 오픈, 시도 횟수 +1, 짝 판정 |
| 같은 카드·찾은 카드 선택 | 유효하지 않은 선택 | 아무 변경 없음 |
| 판정 중 추가 선택 | `isResolving`이 참 | 무시, 세 번째 카드 오픈 금지 |
| 다음 라운드 | ROUND_CLEAR, 50 미만 | 누적값 유지, 라운드 +1 |
| 포기 | PLAYING 또는 ROUND_CLEAR | 현재까지의 누적 총점으로 게임 종료·점수판 공개 |
| 새 게임 | GAME_OVER | 1라운드·누적 0점으로 초기화 |
| 처음으로 | 결과 또는 순위 화면 | READY로 복귀 |
| Tab, Enter, Space | 활성화된 버튼에 초점 | 이동 및 클릭과 동일한 처리 |
| 다른 탭으로 이동·복귀 | 진행 중 | 일시정지하지 않음, 복귀 시 실제 종료 시각으로 재계산 |
| 캐릭터 선택 | READY이고 준비 중이 아님 | 남자 또는 여자 캐릭터 미리보기와 선택값 변경 |
| 배경음 음소거·볼륨 | 모든 화면 | 배경음만 즉시 변경, 게임 타이머에는 영향 없음 |
| 효과음 음소거·볼륨 | 선택 기능 사용 시 | 효과음만 변경 |

클릭 이벤트 하나를 공통 진입점으로 사용한다. 터치와 클릭을 따로 중복 등록하여 한 번의 탭이 두 번 처리되지 않게 한다. 모든 카드 선택은 시간 초과 검사를 먼저 수행한다.

| 정리 처리 | 예약 해제, 선택 초기화, 오래된 콜백 무효화 | 필수 |
| 플레이어 정보 | 별명·나이·성별 입력 검증, 캐릭터와 독립 | 확정 추가 |
| 기록 저장·순위 | 게임 전체 누적 종료 기록과 설정 저장, 총점 순위 표시 | 확정 추가 |
| 배경음 | 180초 음악 반복 재생, 중복 방지, 개별 음량 제어 | 확정 추가 |
| 사용자 캐릭터 | 남자·여자 선택과 게임 이벤트별 2D 애니메이션 | 확정 추가 |
| 사운드 | 오픈·일치·불일치·성공·실패 효과음, 음소거 | 선택 |
| 테마·축하 효과 | 이모지 테마와 간단한 성공 연출 | 선택 |

짝당 100점과 성공 라운드의 남은 정수 초×10점 보너스를 게임 전체에 누적한다. 다음 라운드에서도 누적 총점을 유지하고 HUD에 표시한다. 종료 시 마지막 미완료 라운드의 짝 점수도 포함하되 시간 초과·포기에는 새 보너스를 주지 않는다. ROUND_CLEAR에서 포기하면 이미 합산한 라운드를 다시 더하지 않는다. 총 플레이 시간은 실제 각 라운드의 진행 시간 합계이며 완료 안내·결과·순위 화면 대기 시간은 제외한다. 새 게임에서만 누적값을 0으로 초기화한다. 오답 감점은 없다. 짝은 `pairId`로 판정하고 사운드는 첫 사용자 조작 이후 활성화한다.

### 확정 추가 연출: 배경음과 사용자 캐릭터

**배경음:** 3분(180초, 인코딩 오차 ±1초)의 상큼발랄한 보컬 없는 음악 1곡을 로컬 파일로 제공한다. 제작 방향은 약 120~130 BPM, 밝은 신스·플럭·벨과 가벼운 드럼을 사용한 경쾌한 팝이다. 반복 연결부의 갑작스러운 끊김과 음량 변화를 피하고 카드 효과음이 들리도록 기본 배경음 볼륨은 30%, 효과음은 70%로 둔다. 두 볼륨은 각각 0~100%로 조절하며 별도 음소거를 제공한다. 3분은 음악 길이이며 라운드 제한 시간은 기존 표를 따른다.

최초 페이지 진입에는 자동 재생하지 않는다. 시작 버튼 조작으로 재생을 요청하며 플레이·라운드 완료 안내·다음 라운드·최종 결과·순위 사이에는 같은 곡을 이어 반복한다. ‘처음으로’는 정지·0초 초기화, 종료 후 ‘새 게임’은 0초부터 재생한다. 숨겨진 탭에서는 음악만 일시정지하고 PLAYING의 시간은 계속 흐른다. ROUND_CLEAR에서는 타이머가 이미 멈춰 있다. 복귀 시 시간을 먼저 재검사하고 음소거가 아니면 기존 위치에서 재생을 요청한다. 거부 시 수동 재생 버튼을 제공한다.

**캐릭터:** 남자와 여자 캐릭터 각 1종을 제공한다. 입력한 성별과 관계없이 자유롭게 고르며 능력치·점수·시간 차이는 없다. 저장 설정이 없으면 남자 캐릭터가 기본값이다. 선택은 다음 라운드·새 게임·처음으로 이동 시 유지하며 변경은 READY에서만 가능하다. 저장 가능 시 새로고침 후 선택 캐릭터를 복원한다.

요청한 현대적이고 상큼발랄한 느낌을 위한 디자인 방향은 2~3등신의 둥근 실루엣, 또렷한 표정, 깔끔한 선, 민트·코랄·레몬색 포인트와 캐주얼 의상이다. 남녀 모두 같은 화풍과 완성도로 제작하며 색상과 동작을 성별 고정관념으로 구분하지 않는다. 이는 제작 제안이며 특정 유행 순위나 기존 작품 캐릭터를 복제하는 요구가 아니다.

| 동작 | 발생 조건 | 재생 규칙 |
| --- | --- | --- |
| 대기 | READY 및 일반 플레이 | 눈 깜빡임·가벼운 호흡, 2~3초 반복 |
| 반가움 | 캐릭터 선택·게임 시작 | 손 흔들기 0.8초 후 대기 |
| 응원 | 짝 일치 | 작은 박수 0.6초 후 대기 |
| 격려 | 짝 불일치 | 부드러운 고개 끄덕임 0.5초 후 대기 |
| 성공 | 라운드 성공·전체 완료 | 기뻐하는 동작 1.2초 후 성공 포즈 유지 |
| 실패 | 시간 초과·사용자 포기 | 아쉬움 뒤 응원하는 동작 1초 후 격려 포즈 유지 |

각 캐릭터의 6종 동작을 투명 배경 PNG와 CSS 단계식 애니메이션으로 구성한다. 기존 대기 시트(4×1)와 새 반응 시트(4×5)를 사용하며 각 반응은 시트의 한 행이다. 별도 정적 대체 시트 파일도 제공하고 프레임 크기·수·행·재생 시간을 config.js에 정의한다. 결과 동작은 일반 반응보다 우선하며 연출 종료를 기다려 판정이나 다음 라운드를 지연하지 않는다. 캐릭터 애니메이션은 카드의 0.5초 복구와 별도로 실행하고, 이전 판의 애니메이션 예약도 정리한다. 움직임 감소 설정에서는 행별 정적 포즈를 사용한다. 파일 구성은 assets-manifest.md를 따른다.

## 8. 오류를 예방하기 위한 예외 상황

| 상황 | 예방 및 처리 |
| --- | --- |
| 빠른 연속 클릭, 같은 카드 반복 선택 | 상태·잠금·선택 ID·일치 여부를 검사한 뒤에만 처리 |
| 마지막 짝과 시간 초과가 겹침 | 두 번째 선택 처리 시작 시 시간을 확인하고, 남아 있으면 즉시 판정·성공 확정; 0 이하면 실패 |
| 불일치 복구를 기다리는 중 시간 초과 | 즉시 실패 확정, 복구 예약 취소, 카드 입력 차단 |
| 새 게임 후 이전 콜백 실행 | 예약 해제와 `gameId` 비교를 함께 사용 |
| 시작·다음 라운드 버튼 연속 입력 | 준비 잠금과 상태 검증으로 판과 타이머를 한 번만 생성 |
| 탭 비활성화로 타이머 호출 지연 | 호출 횟수로 시간을 차감하지 않고 종료 시각으로 재계산 |
| 잘못된 라운드, 홀수 카드 수, 부족한 이모지 | 렌더링 전에 검증, READY 유지, 오류 안내; 잘못된 판 시작 금지 |
| 50라운드 다음 진행 요청 | 다음 라운드 버튼 숨김과 로직 검증으로 51라운드 진입 차단 |
| 화면 크기 변경 | 카드 순서와 상태를 보존하고 CSS 배치만 변경 |
| 저장 데이터 손상·저장 차단 | 예외 처리 후 기본값 사용, 현재 게임 유지 |
| 오디오 누락·재생 차단 | 무음으로 계속 진행, 배경음 켜기 버튼으로 사용자 조작 후 재시도 |
| 배경음 중복 재생 | 하나의 오디오 인스턴스만 재사용, 라운드 전환 때 새 인스턴스 생성 금지 |
| 캐릭터 이미지 누락 | 정적 대체 이미지, 그것도 없으면 캐릭터 이름 표시; 게임 시작 지연 금지 |
| 캐릭터 반응 연속 발생 | 기존 복귀 예약 취소 후 최신 반응 적용, 결과 동작 우선, 이전 gameId 콜백 무시 |
| 닫힌 카드의 정답이 보조 기술에 노출 | 접근성 이름과 숨김 속성도 카드 공개 상태에 맞게 갱신 |
| 완료 안내 중 포기·종료 버튼 연속 입력 | ROUND_CLEAR와 GAME_OVER 구분, roundSettled와 종료 상태 검사로 중복 합산·중복 저장 방지 |

확정 설정의 최대 카드 수는 48장이다. 서로 구별되는 이모지 24종 이상을 준비하고, 라운드별 카드 수와 이모지 수를 함께 검증한다. 잘못된 설정은 임의로 축소하지 않고 오류로 처리한다.

## 9. PC와 모바일 반응형 조건

- `viewport`를 설정하고 CSS Grid를 사용한다. 화면 너비 320px 이상에서 가로 스크롤과 영역 겹침이 없어야 한다.
- PC(1024px 이상): 콘텐츠 최대 너비 960px, 중앙 정렬, 상태 정보 가로 배치, 확정된 기본 열 수 사용.
- 태블릿(600~1023px): 좌우 여백 20px, 상태 정보 줄바꿈 허용, 카드 판 최대 6열.
- 모바일(320~599px): 좌우 여백 16px, 상태 정보 2~3열, 카드 판 최대 4열. 2×2 라운드는 2열을 유지한다.
- 카드 수는 화면 크기와 무관하게 동일하다. 모바일에서 카드가 많으면 세로 스크롤을 허용하고 상태 정보는 상단에서 확인할 수 있게 한다.
- 카드 간격은 최소 8px, 카드와 주요 버튼의 터치 영역은 최소 44×44px을 목표로 한다. 카드 앞면 이모지가 잘리지 않아야 한다.
- hover에만 의존하지 않고 키보드 초점과 선택 상태를 명확히 표시한다. 화면 확대와 세로 스크롤을 막지 않는다.
- `prefers-reduced-motion`에서는 뒤집기 움직임을 줄이되 불일치 카드 공개 시간은 유지한다.
- 시간 경고는 남은 표시 시간이 10초 이하일 때 색과 텍스트로 표시한다. 마지막 짝에는 일치 효과음보다 성공 효과음을 우선한다. 배경음 탭 복귀 재생은 이미 시작한 게임의 플레이·라운드 완료 안내·결과·순위 화면에서만 요청하며 READY에서는 자동 재생하지 않는다.
- PC에서는 캐릭터를 카드 판 옆 별도 영역에, 모바일에서는 상태 정보 위 작은 별도 영역에 배치한다. 캐릭터 때문에 카드 터치 영역을 줄이거나 카드를 가리지 않는다. 움직임 감소 설정에서는 캐릭터를 상태별 정적 포즈로 표시한다.
- 320px, 375px, 768px, 1280px 너비와 모바일 가로 방향을 확인한다. 창 크기 변경과 회전은 게임을 초기화하지 않는다.

## 10. 기능 구현 순서

1. **기본 구조:** HTML 영역, CSS 기본 배치, 설정 파일과 스크립트 연결을 만든다.
2. **상태와 준비:** READY/PLAYING/ROUND_CLEAR/GAME_OVER, 초기화·정리 함수, 1라운드 설정 검증을 구현한다.
3. **카드 판:** 2×2 카드 생성, 셔플, 동적 버튼 렌더링을 구현한다.
4. **입력과 뒤집기:** 클릭·터치·키보드 공통 처리와 CSS 애니메이션을 연결한다.
5. **짝 판정:** 두 장 제한, 일치 유지, 불일치 0.5초 복구, 시도·남은 쌍 갱신을 구현한다.
6. **시간과 결과:** 종료 시각 기반 타이머, 점수, 성공·실패, 종료 중복 방지를 구현한다.
7. **게임과 라운드 구분:** 1~49 완료 안내·누적 점수 유지·다음 라운드, 시간 초과·50 전체 완료·포기의 최종 총점 확정, 종료 후 새 게임·처음으로를 연결한다.
8. **반응형과 접근성:** 최대 카드 수에서 PC·모바일 배치, 초점 이동, 움직임 감소 설정을 검증한다.
9. **확정 추가 연출:** 남자·여자 캐릭터 자산과 선택 UI, 상태별 애니메이션, 3분 배경음과 개별 음량 제어를 연결하고 모바일·탭 복귀·재시작을 검증한다.
10. **플레이어 정보·순위:** 시작 전 입력 검증, 로컬 종료 기록 저장, 결과 → 순위 → 다음 도전 흐름과 저장 실패 대체를 연결한다. 선택 효과음도 기존 파일로 적용한다.
11. **최종 확인:** 예외 상황과 난이도 경계를 검증하고 실행 방법 및 테스트 결과를 문서화한다.

## 11. 기능별 완료 조건

| 기능 | 완료 조건 |
| --- | --- |
| 실행 환경 | 로컬 index.html에서 네트워크 없이 시작·플레이·결과 동작, 필수 자산 오류 없음 |
| 난이도 설정 | 확정 표와 시간 계산식이 1~50라운드에 적용되고 최대 48장·24쌍 및 라운드별 제한 시간이 일치 |
| 카드 생성·셔플 | 모든 카드 ID가 고유하고 각 pairId가 정확히 두 번 존재, 셔플 전후 카드 구성 동일 |
| 렌더링 | 설정된 카드 수가 표시되고 첫 시작 시 모두 뒷면, 모바일 재배치 후에도 순서와 상태 유지 |
| 입력·애니메이션 | 클릭·터치·키보드로 한 장씩 선택 가능, 같은 카드 재선택과 세 번째 카드 입력 무시 |
| 짝 판정 | 일치한 카드 유지, 불일치 시 두 번째 선택 후 500ms 예약으로 복구; 브라우저 지연을 제외하고 불필요한 추가 대기 없음 |
| 시도·점수 | 유효한 두 번째 선택마다 시도 +1, 짝당 100점, 성공 보너스 한 번, 실패 보너스 0점 |
| 타이머 | 입력 가능 시점부터 시작, 음수 표시 없음, 탭 복귀와 카드 입력 시 실제 남은 시간 반영 |
| 결과 | 시간 초과·50 전체 완료·포기에만 누적 총점 공개·게임 기록 1개 저장. 1~49 성공은 완료 안내만 표시 |
| 상태 전환 | PLAYING에서만 판정, ROUND_CLEAR에서 다음 라운드 또는 포기, GAME_OVER에서 최종 결과·새 게임 |
| 정리·새 게임 | 불일치 대기 중 포기와 새 게임에서도 이전 예약이 새 판을 변경하지 않음 |
| 라운드 진행 | 1~49 완료마다 누적 유지, 50 성공 후 51 진입 불가, 종료 후 새 게임은 1라운드·0점 |
| 반응형·접근성 | 지정 너비와 가로 방향에서 겹침·가로 넘침 없음, 터치·초점 조작 가능, 닫힌 정답 노출 없음 |
| 플레이어 정보·로컬 순위 | 필수 입력 검증, 나이·성별 비저장, 구 라운드 기록 분리, 누적 총점·공동 순위·중복 저장 방지, 손상·차단 대응 |
| 사운드 — 선택 | 사용자 조작 후 재생, 음소거 동작, 누락·재생 실패 시 게임 유지 |
| 배경음 — 확정 추가 | 180초(인코딩 오차 ±1초) 음원, 자연스러운 반복, 라운드 간 이어 재생, 개별 음소거·볼륨, 탭 전환·재시작 시 중복 없음 |
| 사용자 캐릭터 — 확정 추가 | 두 캐릭터 선택·유지 및 모든 상태별 동작 확인, 카드 가림 없음, 정적 대체·움직임 감소 지원, 점수와 시간에 영향 없음 |
| 최종 문서 | README에 실행·조작법을 기록하고 테스트 체크리스트에 실제 확인 결과와 남은 문제를 기재 |

전체 완료는 필수 기능과 확정 추가 연출의 완료 조건을 모두 통과하고 확정된 최대 카드 수의 플레이 가능성을 확인한 시점이다. 선택 기능은 구현한 경우에만 해당 완료 조건을 적용한다.
